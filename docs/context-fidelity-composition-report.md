### Caso 5, repetição 1

**group-generation**

`string.Length` em C# conta **unidades de código UTF-16**, não grafemas.

Exemplos:

```csharp
"abc".Length              // 3
"😀".Length               // 2 — um caractere Unicode, dois code units UTF-16
"e\u0301".Length          // 2 — “e” + acento combinante, visualmente um grafema
"👨‍👩‍👧‍👦".Length        // 11 — vários code points unidos por ZWJ
```

Se você precisa contar **elementos de texto** — algo mais próximo de grafemas — use `StringInfo`:

```csharp
using System.Globalization;

int quantidade = new StringInfo(texto).LengthInTextElements;
```

Para contar **code points** — valores Unicode, sem contar pares substitutos separadamente — pode enumerar `Rune`:

```csharp
using System.Text;

int quantidade = texto.EnumerateRunes().Count();
```

Resumo, porque Unicode gosta de transformar uma pergunta simples num pequeno tratado:

- `string.Length`: unidades UTF-16;
- `EnumerateRunes()`: code points;
- `StringInfo`: elementos de texto, mais próximos dos grafemas visuais.

### Caso 5, repetição 2

**group-generation**

`string.Length` em C# conta **unidades de código UTF-16** (`char`), não grafemas.

Exemplos:

```csharp
"abc".Length        // 3
"😀".Length         // 2 — surrogate pair
"e\u0301".Length    // 2 — "e" + acento combinante
```

Assim, um único caractere visual pode ocupar duas ou mais unidades UTF-16. Para contar elementos de texto mais próximos de **grafemas**, use `StringInfo`:

```csharp
using System.Globalization;

int grafemas = new StringInfo(texto).LengthInTextElements;
```

E, para contar pontos de código Unicode — sem necessariamente contar grafemas — considere `System.Text.Rune`. Unicode, naturalmente, decidiu que “um caractere” seria simples demais.
